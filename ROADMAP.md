# Roadmap

Phase 1 is the whole of this repository's current scope: **one command**, `/property-audit`, for Switzerland, in four languages. Later phases are listed so contributors know where things are going; they are not commitments and not accepted as pull requests before their time (see `docs/topoli_product_spec_v2.md` §7).

| Phase | Name | Core question answered | Primary metric | Ships |
|---|---|---|---|---|
| **1** | Skill + aha + website | "What can I do with this address?" | Stars, waitlist | `/property-audit` · federal baseline adapters · Zürich as first deep canton · evidence model · HTML report · share artefacts · FR/DE/IT/EN |
| 2 | Construction events | "What is changing around here?" | Repeat usage, shares | `/nearby-construction` · Geneva, Basel-Stadt, Zürich event adapters · timeline in the report |
| 3 | Multi-agent + contribution ecosystem | "Can anyone add a canton or an agent?" | External contributors, jurisdictions | `/development-potential` · adapter SDK · Cursor / Codex / ChatGPT / Gemini / MCP / CLI adapters · coverage dashboard |
| 4 | Paid-demand test | "Which workflow do people pay for?" | Waitlist→intent conversion | `/construction-leads` and `/renovation-opportunities` as previews |
| 5 | First paid wedge | "Can we sell it?" | Paying customers, retention | Hosted layer (separate product); the open skill stays fully functional |
| 6 | France | "Is this a platform, not a Swiss proptech?" | French usage, adapter reuse | `countries/fr/` adapters |
| 7 | Construction knowledge graph | "Do we own the infrastructure?" | Data assets, API adoption | History, entity resolution, change detection |
