# WO-05 — Zürich: zoning, BZO regulation extraction, development potential

**Read first:** PRD (repo) §4.2, §3.2 steps 5–6, §3.6; spec §8 evidence graph, §10.
**Depends on:** WO-03, WO-04.

## Objective
For any parcel in the City of Zürich: zone code + name (class A), extracted numeric rules with article-level evidence spans (class A with spans), and a class-C development-potential estimate whose formula and inputs are shown. Other ZH municipalities: zone code from the cantonal layer, rules class D with the "not yet contributed" stub.

## Tasks
1. `countries/ch/zh/zoning.py` — cantonal/municipal zoning layer (WFS/WMS identify) → zone code, zone name, plan reference; verify licensing and record.
2. `countries/ch/zh/regulation/` — source: the City of Zürich BZO (Bau- und Zonenordnung) consolidated text (fetch the official published version; record URL, version date, and store a local copy only if the licence allows — else fetch on demand and cache).
   - `parser.py`: rule-specific extractors (not generic LLM extraction) for, per zone: Ausnützungsziffer / Baumassenziffer, max full floors, max building height, setback rules (Grenzabstand), Mehrlängenzuschlag if present. Each extracted rule = `Regulation` with `evidence_spans` (article no., verbatim span, char offsets) and `parser_version`.
   - Build a `zones.yaml` table generated by the parser and checked into `countries/ch/zh/regulation/generated/`; a test diff-checks it against the live parse so drift is caught.
   - Anything the parser cannot extract deterministically stays absent → class D downstream.
3. `core/scoring/potential.py` — `compute_potential(parcel, buildings, rules)`: theoretical allowed floor area from the zone's density rule × parcel area (state which rule and definition were used), existing floor area from GWR (floors × footprint, flagged as approximation), utilisation ratio, headroom in m² and as "roughly X% of what zoning appears to allow". Output class C with `derivation` containing the formula and every input value + source. Never output apartment counts, values or costs.
4. Layer-1 section 5 rendering data: rule table with article citations and effective dates; layer-0 finding template only fires when class C inputs are all present.
5. Heritage: `countries/ch/zh/heritage.py` — municipal inventory of protected buildings (Inventar der kunst- und kulturhistorischen Schutzobjekte); listing status class A.
6. Architect review harness: `topoli review export --addresses tests/review/zh20.txt` writes a spreadsheet-friendly CSV (address, zone, each rule, potential inputs/result, source URLs) for the 20-audit review in PRD §10; `tests/review/README.md` explains the error definition.
7. `docs/decisions/00x-zh-density-definition.md` — document which density definition the BZO uses and how existing floor area is approximated; this is where an architect's correction lands.

## Done when
For 10 City of Zürich fixtures across ≥ 5 zone types, `topoli regulation <address>` prints rules with article spans and a potential estimate whose derivation lists every input; a Winterthur address returns zone code + class D rules + contribution stub; `zones.yaml` diff test green.
